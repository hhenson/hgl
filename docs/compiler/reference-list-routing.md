# Fixed REF-list routing

The Rust engine supports the Spec’s [guarded REF-list selector](../../external/hgraph_spec/language/docs/design/type-extensions.md#selecting-and-forwarding-a-reference) for fixed `list<ref<T>, N>` inputs. Connection lists preserve each REF carrier; selected entries can retarget while the index is silent. Bounds are checked before child access. Ordinary followers receive target publications independently of the selector.

The [shared suite](../../crates/hgl-program/tests/fixtures/reference_list_routing.hgl) contains five groups/seven evaluations for guards, invalid targets, retargeting, identity, bytes and sparse maps. Its [provenance](../../crates/hgl-program/tests/fixtures/reference_list_routing.PROVENANCE.json) matches Std `d82bcc3`. Nine local groups/ten evaluations cover projections, nominal assemblies, conditional entries, aliases and ordinary scalar lists. REF-valued child projections preserve the inner designation, follow selected-child retargeting while the parent is silent, and unbind an ordinary follower when the new selected child has not published. Compiled bounds controls require errors for `-1`, `N` and `i64::MAX`, and success for `0` and `N-1`. Successful cycles, startup and cleanup allocate zero.

Ordinary REF-list publishers and unproved target preparation retain explicit Rust diagnostics. Dynamic graph collection selection and unbounded-list safe indexing remain outside this implementation. Map absent-key connection selection still needs a precise source contract; membership and reference expiry already follow TS-11/23.
